## 排查 git push 到 GitHub 报 "Repository not found"

**问题**：本地 main 分支有 2 个提交，push 到 GitHub 一直报 `remote: Repository not found`。

**真正根因**：仓库名拼写不一致。
- 本地 remote 写的是 `Monetyg/health-manage-system`（正确拼写 system）
- GitHub 上真实存在的仓库是 `Monetyg/health-manage-systeam`（拼错的 systeam，2026-09-29 22:39 创建，public 空仓库）
- 与本地目录名 `heahth_manage_systeam` 同源的手误

**已被证伪的假设**（记录以免重复排查）：
- ❌ remote URL 多余斜杠 —— 原地址本就干净，报错文本末尾的 `/` 是 git 打印错误信息时自己补的
- ❌ Windows 凭据管理器缓存旧凭据 —— `cmdkey /list` 无任何 github 条目
- ❌ Git 内置 ssh 与 OpenSSH 不兼容 —— 与本次故障无关，SSH 已放弃
- ❌ 全局 credential.helper 需 unset —— 全局本就没有该项；系统级为 Git for Windows 默认的 `credential.helper=helper-selector`，不应清除

**关键排查手段**：用 GitHub API 匿名交叉验证，比反复试 push 高效得多
- `curl https://api.github.com/repos/<owner>/<repo>` → 404 说明仓库名不对或私有
- `curl https://api.github.com/users/<owner>/repos?per_page=100` → 拿到真实仓库名列表，一击定位拼写差异

**修复动作**：`git remote set-url origin https://github.com/Monetyg/health-manage-systeam.git`（本地已改完，匿名探测返回 200）

**待用户执行**：嵌入 token 推送 → `git push -u origin main` → 重置 remote 移除 token

**环境**：Windows 11 / Git 2.55.0.windows.3 / 项目路径 D:\cursor-all-project\heahth_manage_systeam

- `.git/packed-refs` 无 origin 条目
- `cmdkey /list` 无 github 条目
- `git status` 只显示 `On branch main`，无 `up to date with 'origin/main'` 行 → 上游未建立

**重要推论**：用户此前"图形登录弹窗登录完仍报仓库不存在"——认证其实成功了，是认证通过后 GitHub 查 `health-manage-system` 查不到才回 404。说明认证链路一直是通的，唯一故障点就是仓库名。修正地址后图形登录应可直接走通，不必强上 token。

**教训**：以后给用户分节编号的命令清单，"诊断/校验"与"实际执行"要分开标注清楚，避免用户只跑了只读命令就以为完事了。
